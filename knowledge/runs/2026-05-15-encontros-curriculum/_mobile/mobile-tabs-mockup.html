Mobile tabs · agent-driven focus · 2026-05-15

The mobile CBO surface as a single-pane app with bottom tabs. The agent drives which tab is in focus — when it invokes a microapp, the UI auto-switches. Chat input only lives on the Chat tab. Microapp tabs have a single concern (make a selection); the user taps back to Chat to message the agent.

Reading the mockup · 5 screens in narrative order, showing the agent–user back-and-forth across tabs. Each screen is one moment in time; each annotation explains what just happened and the relevant state changes.

Agent drives the UI

The agent's open_map tool call carried site-selection parameters. The UI did three things at once:

  1. Made the Mapa tab visible (it wasn't before)
  2. Auto-switched to it
  3. Rendered the agent's prompt as a banner above the map

The chat input is now hidden. This tab has one concern: the map selection. To ask the agent a question, the user taps 💬 Chat.

The "← Voltar ao chat" link in the banner is an explicit escape hatch — for users who don't notice the tab bar.

state.mobileActiveTab = 'map' state.openMapParams = { selectionMode: 'site', zoneSource: 'neighborhoods', ... } state.agentPrompt = "Marque seu local no mapa…" Visible tabs: ['chat', 'map', 'perfil']
User drops a pin · taps "Confirmar seleção"

The auto-return

When the user taps Confirmar seleção:

  1. The map's selection result is posted to the agent (becomes a user chat message)
  2. UI switches back to Chat
  3. Agent streams its response in the chat panel
  4. Mapa tab stays in the tab bar — the user can return to adjust without re-invoking

Note the user message is rendered with a 📍 emoji + a short summary, not the raw geo-JSON the agent receives. Two views of the same data.

state.mobileActiveTab = 'chat' (auto-set) state.openMapParams = STILL SET (tab stays available) last user message: type: 'map_selection', display: '📍 Site marcado em Cascata', payload: { lat, lng, area_m2, ... }
User taps Perfil tab while agent is still typing the next question

Perfil is read-mostly

The Perfil tab is a friendly summary view of the doc panel. Each completed card has an "Editar" link → opens an inline editor (existing EditableField pattern). No phase numbers, no scores — what the CBO sees about themselves.

Future encontros' cards appear muted with "— próximo encontro" so the CBO has a sense of the arc.

Note the 🔴 dot on Chat — that appeared when the agent's response landed while the user was on Perfil. Tapping Chat clears it.

state.mobileActiveTab = 'perfil' state.mobileChatUnread = true (set when a content message arrived on a non-chat tab)
Later in Encontro 3 · agent invokes the Intervention Selector

Multiple contextual tabs coexist

By Encontro 3, the user has accumulated two microapp tabs: Mapa (still available from E2) and Intervenções (just opened). Both persist; the agent's most recent invocation drives the active tab.

The "★ Indicado" badges on intervention cards are pre-filtered by the agent based on the CBO's selected hazard (enchente from E2). Other NBS types are still visible but de-emphasized.

Same banner pattern: agent prompt above, microapp body, confirm action at the bottom, tab bar last.

state.mobileActiveTab = 'interventions' state.openMapParams = STILL SET state.interventionSelectorParams = { preFilteredHazards: ['flood'], selectionMode: 'single', } Visible tabs: ['chat', 'map', 'interventions', 'perfil']

EDGE CASES — handled by the spec

Mid-typing in Chat → agent invokes microapp. Chat input draft is preserved across tab switches. The user's half-typed text remains when they switch back.
Two microapps active simultaneously. Both tabs visible. Most recently invoked is the active one. User can switch via tabs to revisit either.
User dismisses by switching away mid-selection. No data loss — the microapp's local state persists. Returning to the tab restores the in-progress selection.
Streaming agent response while on a non-chat tab. 🔴 dot appears on Chat as soon as the first content message lands; doesn't update mid-stream to avoid flicker.

Desktop is unchanged

Above 768px, the existing split-screen layout stays as it is. Same agent-driven tab logic (the rightTab state), just rendered as a sidebar instead of full-screen panels.
