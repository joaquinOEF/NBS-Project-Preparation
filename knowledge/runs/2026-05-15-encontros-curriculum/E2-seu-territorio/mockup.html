Why "seu território" not "seu site"

Per the Sustainable Favela Network's ABCD framing, we lead with the territory the community knows — not a technical "site." The educational moment (NBS examples) comes first, the technical moment (map) comes second.

The preamble is path-agnostic. The agent's first message after "Começar" differs based on path.

MapMicroapp · IMPROVEMENT — simplified legend + single hazard filter

Today the map shows all 48 layers with a busy legend. For E2 mobile, the agent passes selectionMode: 'site' + hazardFilter: ['flood'] + showLegendSimple: true. Map shows only Cascata polygon + flood gradient + 3-chip legend. Single-pin draw mode.

For the has-idea path the agent already knows the bairro's primary hazard from the bairro polygon's primaryHazard property — so we filter to just that hazard. Reduces cognitive load.

open_map params for has-idea: { selectionMode: 'site', centerBairro: 'cascata', hazardFilter: ['flood'], showLegendSimple: true, }

MapMicroapp · IMPROVEMENT — browse-only mode (NEW)

No "Confirmar local" button — instead, a "Pronto, vamos escolher um local" pivot that switches the map into selectionMode: 'site' when the user is ready. They aren't being asked to commit; they're being invited to explore.

Per the LEED-UP + ABCD methodology: community knowledge first, technical decision second. The agent's banner explains what the colors mean instead of asking a question.

Note the red dot on 💬 — the agent has already sent a follow-up message ("Olha sem pressa, me conta o que você vê") that the user will read when they return to Chat.

open_map params for needs-help (initial): { selectionMode: 'browse-only', centerBairro: 'restinga', hazardFilter: ['flood', 'heat', 'landslide'], showLegendSimple: true, pivotCta: 'Pronto, vamos escolher um local →', pivotTo: { selectionMode: 'site' } }

RiskPriorityChips · NEW microapp (inline)

3 hazards, ordered by user concern. Drag handles for desktop; tap-in-order for mobile (1st tap = 1, 2nd = 2, 3rd = 3). The first 2 are required (primary + secondary); the 3rd is optional.

Per the US Climate Resilience Toolkit + UN-Habitat, qualitative ranking is the right rigor at the community level. We're not asking the user to assign quantitative scores — just to order them.

component: RiskPriorityChips agent event: ask_priority_rank params: { question: "...", items: ['flood', 'heat', 'landslide'], minRanked: 2, } output: { primary_hazard: 'flood', secondary_hazard: 'heat', tertiary_hazard: 'landslide' }

CommunityAnchoringComposer · NEW microapp (inline)

Three labeled free-text fields + a multi-select chip row. Lighter than a full form, more structured than a single free-text. Captures the texture of community engagement (per BPJP/C40 inclusive-action criteria) without forcing demographic-survey framing.

Each field is optional — they can leave any blank. The chip-row engagement methods feed the Community Anchoring maturity score: ≥1 active method (oficinas/mutirões) → score 2; assembleias regulares (governance) → score 3.

component: CommunityAnchoringComposer output: community_anchoring_lead: "Sandra, D. Maria" community_volunteers: "8 pessoas regulares" community_beneficiaries: "" community_engagement_methods: ['assembleias', 'oficinas']
