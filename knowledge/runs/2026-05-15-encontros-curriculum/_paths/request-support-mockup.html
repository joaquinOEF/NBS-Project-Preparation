RequestSupport · cross-cutting · CBO surface + orchestrator surface

The "Pedir apoio" affordance is available across every encontro. CBOs hit it when they get stuck; coordinator (Julia/Antônia) sweeps the pendency queue. This walkthrough shows the 4 user-facing states.

SCREEN 1 — Chat header · button states across both paths

The button lives in the chat header next to Export and Restart. Tooltip explains. Three states: idle (has-idea), idle (needs-help, more prominent), pending count.

has-idea · idle

Outlined, subtle. Available but doesn't compete with the main flow.

needs-help · idle

Filled emerald. CBOs who arrived "wanting to discover" get a clearer affordance to escalate.

2 pendências

Amber count badge. Once the CBO has any open request, the count replaces the prominent style — they already know to ask.

CBO taps the button → dialog opens

Dialog · core surface

4 option cards keep the choice explicit — coordinators get useful signal from which kind of help is being asked, not just that help is needed.

The optional message tops out at 2000 chars. Most submissions are 1-2 sentences.

Submit button is disabled until a type is picked — message remains optional.

SCREEN 3 — Success · pedido enviado

Single-CTA success state. Sets expectation: 2 business days, you can keep working in the meantime.

Pedido enviado

A coordenadora vai entrar em contato em até 2 dias úteis. Você pode continuar trabalhando aqui — quando ela responder, você vai ver no chat.

Success state · sets expectation

Two pieces of information: when they'll hear back (2 business days) and what to do meanwhile (keep working — the response lands in chat).

The pending count badge on the chat header increments. Next time they open the dialog, they can see their request history (future PR).

What we don't tell them: exactly when/how the coordinator will respond. That's intentional — the coordinator may respond async via the platform, or schedule a call, or message on WhatsApp. The CBO doesn't need to know the channel.

SCREEN 5 — Data model + API

SCHEMA
cohort_members.support_requests:
  jsonb · SupportRequest[]

type SupportRequest = {
  id: string
  type: 'coordinator-chat'
    | 'oef-technical'
    | 'cbo-connection'
    | 'finance-partners'
  message: string | null
  createdAt: string (ISO)
  resolvedAt: string | null
  resolvedNote: string | null
}

Soft cap at 20 per member. Overflow drops oldest resolved first.

ENDPOINTS
POST  /api/cbo-member/:slug
      /support-request
    CBO submits

PATCH /api/cohort/:slug
      /support-request/:id
      /resolve
    Coordinator marks done

GET   /api/cbo-member/:slug
    Returns supportRequests
    + supportPendingCount
