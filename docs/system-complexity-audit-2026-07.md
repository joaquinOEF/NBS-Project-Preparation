## Executive summary

Five moves carry most of the value; everything else sequences behind them.

**1. Cut the two one-tap paths from live CBOs into the legacy demo (DC-1).** The chat header back button (cbo-profile.tsx:1348) and the landing page's CBO card (shared/roles.ts:195, role-selection.tsx:180) both route real invited users into `/sample/project/sample-ada-1` — the English city-prototype demo hub — and the return path drops the token, stranding them in a fresh session. One small PR, and after it the entire ~20k-line legacy client tree becomes URL-only and quarantinable at leisure.

**2. Close the open LLM spend and flag-gate the legacy server (DS-2, DS-3, DS-1 first).** `/api/concept-note/*`, `/api/projects/:id/agent/chat`, and six `/api/impact-model/*` endpoints stream Claude/OpenAI with no auth on prod (conceptNoteRoutes.ts:75/130, agentRoutes.ts:22, routes.ts:1051-1234); the legacy state-machine writes are also unauthenticated. An `ENABLE_LEGACY_ROUTES` flag (mirroring `ENABLE_TEST_ROUTES`, routes.ts:2009) closes it without deleting anything. Non-negotiable prerequisite: `npm i pg` — the DB driver currently resolves only through the *unused* connect-pg-simple package (server/db.ts:2), so any dep pruning before that bricks every environment at boot.

**3. Un-blind the coordinator console (EF-2).** The live cohort's coordinator map renders zero member markers and three KPIs are permanently 0: the map reads `sm.coords` (a field that doesn't exist) instead of `member.site`, and `snapshotSectionsComplete` waits for a client PATCH no client sends (orchestrator-landing.tsx:131-156, cohortRoutes.ts:723). E2 is the site-mapping workshop and its output is invisible to the person running it. Server-side derivation, read-path only, low risk.

**4. Build E3 before Workshop 3 opens (~Jul 22) as one package (EF-1 + EF-3 + LT-6).** There is no encontro-3.md; phase 3 falls back to hardcoded prompts that never resume a deferred site (`site_deferred` has zero readers), phase 5 then instructs scoring metrics that were never collected, and `resolveTurnModel` hard-routes every phase>2 turn heavy so E3 regresses to pre-#333 latency on day one. Author the skill with the deferral-resume opening, make phase-5 refuse to score uncollected metrics, template the E3 entry, and relax routing per-turnKind. This is the single largest scheduled-work item and it has a hard date.

**5. Take the two cheap latency wins after the demo (LT-1 + LT-4).** Turns are LLM-dominated (3.5-8s/round), and two structural fixes attack that directly: split volatile blocks (CURRENT STATE / RECENT CONVERSATION) out of the system prompt so Anthropic prompt caching can actually hit the stable ~8-9K-token prefix (cboAgent.ts:1148), and set `includePartialMessages` so text streams instead of arriving as whole blocks after each round. Together: ~1-3s perceived improvement on every text-bearing turn plus a large input-cost cut — no architecture change.

Everything is sequenced around the **Jul 8-12 Vila Flores demo freeze**: nothing lands on prod before Jul 13 except optionally the legacy-routes flag shipped in its no-op (enabled) position.

## Latency — ranked contributors

Context: turns are LLM-dominated (~3.5s to first event, 1.5-5s per inference round per docs/agent-turn-latency-standards.md). Rank by user-felt seconds:

1. **LT-4 — No token streaming** (M). Text arrives as whole blocks per round (cboAgent.ts:1203-1214, `includePartialMessages` unset); user stares at "Processando…" for the whole round. Fix: enable partial messages, stream deltas, buffer-then-finalize for `detectInlineOptionList`. **~1-3s perceived on every text turn.** Caveats: client sentence-join at cbo-profile.tsx:856-863 must be delta-aware; deltas need a non-persisted event type. Decide vs the CBO-NORM-LAYER whole-turn buffer first or this gets built twice.
2. **LT-1 — Volatile blocks defeat prompt caching** (M). CURRENT STATE/DOCUMENTS/RECENT CONVERSATION/access-policy are concatenated into the system prompt (cboAgent.ts:1148), so the cache prefix never matches across turns even though sysCtx (~8-9K tokens) is phase-stable. Fix: system = sysCtx only; volatile blocks prepend the user prompt. **~1-1.5s off round 1 + ~90% input-cost cut on the prefix — for same-model consecutive turns only** (adaptive haiku/sonnet routing splits the cache). Needs a real-agent E1 regression run (rules reference section names).
3. **LT-6 — Phase 3+ hard-routes heavy with no skill/template** (M). `if (phase > 2) return heavy` (cboAgent.ts:1107) + no encontro-3.md + no zero-model E3 entry template. Not a bug today; **it is the next "agent too slow" field report** the day W3 opens. Bundle with EF-1.
4. **LT-5 — rounds=2 floor on capture turns** (M). update_section then a full second round just to emit the scripted ask_user; **1.5-5s per capture turn, up to ~20s across E1**. Fix: `next_question` param on update_section or client-side batch templates. This optimizes past an accepted standard — pilot on the most mechanical E1 batch only.
5. **DC-3 — 721kB gzip entry chunk** (S). Zero code splitting; site-explorer's static leaflet import defeats the workshop's careful lazy maps (verified by build: leaflet markers in entry chunk, 0 in the lazy MapMicroapp chunk). React.lazy every route. **First-load win for phone-first users**; caveats: OAuthCallback named-export remap, module-registry static import, verify the SSE kickoff effect still fires once.
6. **LT-2 — 5 serial DB roundtrips before model spawn** (S). cohortLanguage (2 SELECTs) + documents block (2) + phase policy (1), same cboStateId thrice across two tables. One JOIN + Promise.all. **~50-200ms/turn** — matters most on light-model fast turns. Prefer invalidate-on-write over TTL cache (coordinator unlocks must take effect promptly).
7. **LT-3 — fullText shipped every turn** (S). `db.select()` all-columns for a 120-char summary line (documentPersistence.ts:90-91). Add `listDocumentSummariesByOrg`, distinctly typed. **Tens of ms; more for doc-heavy orgs.** Keep full rows for search and testRoutes.
