The big picture — one funnel, two scenarios

Both COUGAR cohorts enter the same platform and the same Session-1 org-profile intake. They differ only in pacing and depth — not in code or script. The org profile is the gate ("step zero"): it produces a maturity scorecard the coordinators use to route each org.

Session 1 captures the org's identity and scores 2 of the 9 maturity metrics. Those two — plus a couple of self-reported fields — are also the earliest read on the org's tier (see below). Sessions unlock one at a time; a coordinator opens the next workshop, and the agent only advances when the current phase's metrics are scored.

How it works under the hood — the turn contract

The agent runs on the Claude Agent SDK with a fresh session every turn — no built-in memory. Each turn it rebuilds context from saved state, acts through tools, streams to the screen over SSE, and persists. The hardening work is about making four guarantees hold on every turn:

Load state
In-memory map is the hot path; on a cold reconnect it hydrates from Postgres (state + message history). The agent reads a "current state" summary + the last ~4 turns so it doesn't re-introduce itself.
Validate every tool call fix 1 ✓
Section ids, maturity metrics, and priority flags are checked against the schema. A misspelled metric is rejected with a corrective retry instead of being silently stored — which used to leave the org unable to advance at the end of the session.
Act through tools
ask_user (chips), update_section, score_maturity, open_map, file upload. Each pushes a live event to the UI and mutates state.
End interactive, or recover fix 2 ✓
If the connection drops mid-stream (common on mobile), the server stops writing to the dead socket. If a turn ends with no question and no text, the user gets a tappable Continue chip instead of a blank screen.
Persist durably fix 3 ✓
State + messages flush in one transaction; phase boundaries flush immediately (no 2-second loss window). Edits and uploads are now logged. A finished profile can't vanish on a restart.

Inside Session 1 — the question sequence

~20–30 min, phone-first, Portuguese by default. green = chip buttons   blue = free text. Org name & neighborhood are often pre-filled from the invite, so the agent confirms rather than asks.

  1. Org name (confirm if pre-filled) · contact name · role
  2. Mission — pick a focus or type your own
  3. Legal form · year founded
  4. Team size · paid vs. volunteer split
  5. Prior project scale  → invites an optional document drop
  6. NbS experience
  7. Neighborhood (confirm if pre-filled)
  8. Groups served (multi-select)
  9. Path triage — "I have a project idea" vs "I want help finding one"
  10. A proud moment (optional)

Then, silently: score org_delivery_capacity + team_technical_experience (0–3 each, never shown to the org), render a warm closing, and hand off. The next workshop appears as a green card when the coordinator opens it.

Adaptive tier — one script, calibrated by maturity fix 5

The two metrics Session 1 produces — plus prior-project scale, NbS experience, and whether a real project doc was uploaded — give an early tier read. Tier dials depth and pacing; it is a parameter, not a separate script. It's grounded in the fast-track Gate 2 rubric (level 2+ on Site Control, Org Delivery Capacity, Financial Thinking, Solution Clarity; Community Anchoring a universal gate) — the same rubric the NbS expert uses to map projects. A coordinator can override the inferred tier at any time.

Emerging

NbS-naïve community group. Plain language, concepts hidden, more reassurance. Org-profile only this session.

Developing

Some capacity or experience. Standard depth; a few deeper probes surface.

Advanced

Existing project / implementer. Pushed earlier into governance, regulatory, funding probes that feed bankability. Site + NbS solutions unlock in the same session.

Dead-end at the finish fixed

Was: agent scores a misspelled metric → "next workshop" banner never appears → org stuck with no way forward.
Now: the bad metric is rejected with a corrective retry; the schema feeds server, gate, and banner from one source so they can't disagree.

Phone drops mid-step fixed

Was: server kept writing to a dead socket; a silent turn left a blank screen + a button that derailed the agent.
Now: disconnect is detected and writes stop; an unambiguous stranded turn offers a tappable Continue chip that resumes cleanly.

"Did my profile save?" fixed

Was: a restart in the 2-second save window, or a half-write, could lose the just-finished profile.
Now: one-transaction flush; phase boundaries persist immediately; edits + uploads are logged and survive a reload.

Still open: documents coming out half-English, and a dropped photo / spreadsheet dead-ending — both addressed by fix 4 (session-level language + unified file intake).
