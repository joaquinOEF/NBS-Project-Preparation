What changed after the Workshop 1 → Workshop 2 duplication audit

An inventory of every question asked across both workshops found the platform re-asking things an organization had already answered — and no guard against it, because W2's questions are server templates that bypass the anti-re-ask machinery entirely. Five changes shipped. These screenshots are the result, captured from the running app with an organization that has E1 answers on file and a proposal already uploaded.

The structural finding

Workshop 1 is almost entirely model-driven — of roughly seventeen questions, exactly one turn is a server template. Workshop 2 is the opposite: essentially all sixteen are templates. That matters because the one hard guard in the system — which infers a question's target field from its chip labels and blocks the model when that field is already filled — only runs through the ask_user tool, and only for org_profile. W2's templated questions push their events directly.

So the machinery stops the model repeating itself inside W1, and offers no protection at all against the platform re-asking, in W2, something W1 already stored. Of its 760 lines, the only org_profile field the W2 machine read was the contact's first name, for the closing line.

The five changes

One more, not visible in a screenshot

Document-sourced writes to the site section now go through the same staging gate that org_profile has had. Until today a PDF could write the site's tenure or current use straight into the record as fact, with the only trace a coordinator-facing note saying nobody had confirmed it. Those two fields also drive the site-control score. A document is evidence; the record should hold testimony.
