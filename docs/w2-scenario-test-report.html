NBS Project Builder · COUGAR · scenario test run 31 July 2026

Three organizations went through Workshop 2. Here is what actually happened.

The three roteiros from the test kit were run end to end against the real application at an iPhone viewport, with the real photos and the real PDF. The transcripts below are captured from the running app, not written by hand. One serious problem surfaced, one bug was found and fixed during the run, and four smaller things are worth deciding on.

The serious one: an organization named the slope, and we showed it three families, none of them about slopes

Coletivo Encosta Viva said the thing that worries them is o barranco. Everything downstream honoured that — the photo requests asked for the slope face, the read-back asked about landslide risk. Then the recommendation arrived: Recuperação de Ecossistemas, Infraestrutura Verde Urbana, Agricultura Urbana. Estabilização de Encostas e Solo was not among them — directly beneath a sentence reading "Nada fica descartado".

Seconds later, asked which families interest them, they picked Estabilização de Encostas e Solo: the one family we did not show.

Two separate causes, both confirmed in code. The recommendation still slices to the top three (cboAgent.ts:1359) even though the agreed design and the on-screen copy both say all five appear. And the stated worry does not enter the ranking at all — it routes the photos and the read-back, but rankFamiliasForSite never sees it. Because this organization answered "não sei dizer", no correction applied either, so the ranking ran purely on neighbourhood averages that put heat first.

How the run was done

Each scenario was driven through the real UI at an iPhone 14 Pro viewport in Portuguese, following its roteiro step for step: the same chips, the same typed story, the same files. Nothing was stubbed except the language model behind free-text turns, which does not participate in any of the templated beats being tested. Transcripts, captured fields and the depth read were dumped straight from the app's own endpoints. Spec: e2e/w2-scenarios.spec.ts. Zero JavaScript errors in all three runs.

Findings

 WhatEvidenceStatus
F-1 Only three of five families are shown, while the copy says nothing is ruled out Org 2 saw 3 families; ranked.slice(0, 3) at cboAgent.ts:1359. The agreed design and the on-screen sentence both promise five. open
F-2 The stated worry never reaches the ranking Org 2 named the slope; rankFamiliasForSite receives risks, bairro, current use and site name — not site_worry. Combined with F-1, the family matching their only concern disappeared. open
F-3 The agent could not see a file that was sitting in the organization's own drawer Org 3's PDF extracted correctly and was linked to the session, but org_id was null, and doc-awareness used the org-only lookup while the user's drawer uses a session-scoped one. The agent asked for the story as if nothing had been sent. fixed during the run
F-4 Three photos cannot be attached in one go The file input has no multiple attribute, so the beat that asks for three photos accepts them one tap at a time. Org 1's upload failed outright when three were selected. open
F-5 Recommendation cards repeat the same opening sentence verbatim Org 2: three cards all begin "Calor é médio no Vila São José." Org 3: three all begin "Vocês disseram que calor aqui é pior…". Reads as generated rather than reasoned. open
F-6 Portuguese gender agreement in the templated why-lines "Essa família age principalmente no enchente" — should be "na enchente". Visible to every reader in the cohort. open
F-7 Redundant disagreement entries Org 1 produced three, two of which state the same fact ("our data ranks heat highest but they named flooding" / "they named flooding, which our data scores low"). open
F-8 Blob storage failure is silent Locally the original file upload to blob storage fails (no bucket configured) and nothing surfaces; only the database row and extracted text survive. Harmless here, but in production it would mean the original file is quietly unrecoverable. environment · worth a guard

What worked, and is worth keeping

  • Photo requests routed correctly by the stated worry in all three runs — water, slope and heat prompts each appeared where they should.
  • The scale message fired for the 2024 story and stayed silent for the everyday-water one.
  • A correction genuinely changed the recommendation and was quoted back in the organization's own terms.
  • "Não sei dizer" was treated as a real answer, recorded as a known unknown, and handed to the coordination.
  • The no-site path produced a full diagnostic and a depth read where it used to produce nothing.
  • Thirteen taps for the minimum path; no JavaScript errors; no horizontal scrolling at 390 px.

Room for improvement — for /refine

  1. Should the stated worry weight the ranking, and by how much? It is the clearest statement of intent an organization gives us, and today it is diagnostic-only. Weighted too heavily it becomes self-fulfilling; ignored, we get scenario 2.
  2. Show all five families, or keep a top-N? The copy already promises five. If five is right, what does the fourth and fifth look like when the signal is weak — listed plainly, or grouped as "no strong signal"?
  3. What should "não sei dizer" do to the ranking? Currently nothing. It could widen the spread, or leave the hazard open and say so on the card.
  4. Multiple photo attachment — one attribute, but it changes the upload experience; worth deciding deliberately rather than by default.
  5. How much should why-lines vary? Full deterministic variety risks over-claiming, as the earlier "a que mais dá conta" superlative did. Identical sentences are the opposite failure.
  6. Do disagreements need de-duplication and a severity, so the coordination sees one clear signal rather than three overlapping lines?
